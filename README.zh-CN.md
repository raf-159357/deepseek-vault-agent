# DeepSeek Voice Notes

**说一句话，它就变成一篇像样的笔记。**

这是一个 [Obsidian](https://obsidian.md) 插件：用你自己的 DeepSeek API Key，把说的话转成文字、按你的要求整理，然后追加、改写或新建笔记。全程你说了算，写完之前一个字都不会动你的库。

[English](README.md) · [反馈问题](https://github.com/raf-159357/obsidian-deepseek-voice/issues)

---

## 它解决什么问题

Obsidian 擅长存放想法，不擅长**在你不方便打字的时候抓住想法**。

走路时想到一个点子、开完会刚出电梯、躺床上突然想清楚一段逻辑——这些时刻你不会打开 Obsidian、找到那篇笔记、把光标放对位置再打字。等你坐下来，想法已经凉了。

这个插件把这件事压缩成一个动作：

> 说一句话 → DeepSeek 转写并按你的要求整理 → 你看一眼 → 写进笔记

它不是一个"语音转文字"工具，而是一个**语音驱动的写笔记工具**。区别在于：转写出来的是口语，写进笔记的应该是能读的东西。

## 它能做什么

假设你说：

> “记一下今天组会，王老师要补三组实验，下周三之前交初稿，还要先核对 2023 级队列数据。”

插件不会把这段口语原样塞进笔记，而是整理成这样：

```markdown
### 2026-11-14 组会

- 王老师要求补充三组实验
- 下周三之前交初稿
- 优先核对 2023 级队列数据
```

四种写入方式，对应四种场景：

| 模式 | 做什么 | 什么时候用 |
| --- | --- | --- |
| **追加到当前笔记** | 把结果加到笔记末尾 | 日记、会议流水、待办清单——**最常用** |
| **改写当前笔记** | 替换正文，保留 frontmatter | 草稿写完一团乱，让它重排一遍 |
| **改写选中段落** | 只替换你选中的那一段 | 只改一段，不动其他 |
| **新建笔记** | 用生成的标题建一个新文件 | 灵感、速记、临时想法 |

## 安装

### 方式一：BRAT（推荐，手机端唯一可行的方式）

1. 在 Obsidian 里安装社区插件 **BRAT**
2. 打开 BRAT → **Add Beta plugin**
3. 填入 `raf-159357/obsidian-deepseek-voice`
4. 去「第三方插件」里启用 **DeepSeek Voice Notes**

### 方式二：手动（仅桌面端）

从 [最新 Release](https://github.com/raf-159357/obsidian-deepseek-voice/releases/latest) 下载 `manifest.json`、`main.js`、`styles.css`，放进：

```
<你的库>/.obsidian/plugins/deepseek-voice-notes/
```

重启 Obsidian，然后在第三方插件里启用。

> iPhone 的「文件」App 不显示 `.obsidian` 这种隐藏目录，所以手机端**没法手动装**，只能用 BRAT 或下面的 Working Copy 方案。

## 配置：填你自己的 API Key

插件**不自带任何 Key**，也不会替任何人付费。你需要自己申请一个：

1. 打开 [platform.deepseek.com](https://platform.deepseek.com)，注册登录
2. 左侧「API keys」→ 创建 → 复制 `sk-` 开头的那串
3. 充一点余额（`deepseek-flash` 档很便宜，日常记笔记几乎感觉不到扣费）
4. 回到 Obsidian：设置 → 第三方插件 → DeepSeek Voice Notes → 齿轮 → 粘贴 Key → 点 **测试连接**

返回「可用」就说明通了。

## 怎么用

### 电脑上

`Ctrl/Cmd + P` 打开命令面板 → 输入「**语音输入**」→ 四个命令任选一个。

### 手机上（三个入口，任选）

**① 轻点背面**（最隐形）

设置 → 辅助功能 → 触控 → 轻点背面 → 轻点两下 → 新建快捷指令，里面**只放一个动作**「打开 URL」，填：

```
obsidian://deepvoice?mode=append
```

**② 桌面 / 锁屏小组件**

长按主屏空白 → 左上角 ＋ → 添加「快捷指令」小组件 → 长按它 → 编辑 → 选中上面那个快捷指令。点一下等于点一下语音按钮。

**③ Obsidian 内部工具栏**

设置 → 移动端 → 工具栏选项 → 添加命令 → 选「语音输入：追加到当前笔记」。写笔记时键盘上方就多一个按钮。

> iPhone 不把音量键开放给第三方 App，所以「同时按两个音量键」做不到。相机那个是系统私有权限，插件层拿不到。

### 弹窗里的六步

1. 顶部选落点（追加 / 改写全文 / 改写选中 / 新建）
2. 点 **「● 开始说话」**，按钮变成 **「■ 结束并转写（12s）」**，说明真的在录
3. 说完点一下同一个按钮
4. 等 1–3 秒，文字出现在输入框——**这一步必须扫一眼**
5. 点 **「生成」**
6. 看预览，点 **「写入笔记」**

第 4 步别跳过。语音识别会把「笔记」听成「比记」、把「队列」听成「对列」，而 AI 会照着错字往下写。花两秒改掉，比事后改一段话便宜得多。

## 怎么用得顺手

几个真实场景，照抄就行：

**开会 / 组会**——落点选「追加」，打开当天的日志笔记，说完让它整理成条目。

**写论文卡住**——落点选「改写选中」，选中那段别扭的文字，说“把这段理顺，别改我的意思和数据”。

**睡前想法**——落点选「新建笔记」，说“新建一篇叫 XX 的笔记，记三件事：……”直接生成文件。

**整理旧笔记**——落点选「改写全文」，说“把这篇整理成三段，每段加小标题，不要加总结”。frontmatter 会自动保留。

**固定你的风格**——设置里的「额外写作要求」写一句，比如「用中文，只用短句和列表，不要客套话」，之后每次生成都遵守。

## 设置项

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| API Key | 空 | 存在库里的 `data.json`，只发给你配置的地址 |
| 接口地址 | `https://api.deepseek.com` | 用中转或代理时改这里，带不带 `/v1` 都行 |
| 模型 | `deepseek-flash` | 想更强可切 `deepseek-v4-pro` |
| 思考模式 | 关 | 关着更快更省；改写长文时打开效果更好 |
| 语音转写 | 开 | 走 `/v1/tools/asr`；关掉就只用键盘听写 |
| 字数上限 | 4000 | 限制生成内容的长度 |
| 上下文上限 | 6000 | 长笔记只发头 60% + 尾 40% |
| 额外写作要求 | 空 | 会追加到每次的提示里，用来固定文风 |
| 写入前需要确认 | 开 | 关掉就变成全自动，不弹预览 |

## 隐私

- **没有任何遥测**：不收集使用数据、不上报错误、不写远程日志。
- Key 只存在你库里的 `.obsidian/plugins/deepseek-voice-notes/data.json`。
- 只有你**在插件里录音且开着语音转写**时，音频才会发出去。
- 只有你**点「生成」**时，文字才会发给对话接口。
- 只有你**点「写入笔记」**时，你的库才会被修改。
- 唯一的网络目标是你在设置里填的那个地址。

想彻底离线验证：把接口地址改成一个不存在的域名，除了报错之外，插件不会有任何其他行为。

## 常见问题

**点「开始说话」提示打不开麦克风**
iPhone 设置 → 往下翻到 Obsidian → 麦克风 → 打开。回到 Obsidian 重试。

**提示 API Key 无效（401）**
多半是复制时带了空格或换行，重新粘一次。余额为 0 会返回 402。

**按钮一直停在「转写中…」**
Key 没填或网络不通。去设置里点「测试连接」看具体报错。

**「写入笔记」之后内容没变**
大概率是你先选中的是「改写选中」，但选区在弹窗打开后失效了。换「追加」或「改写全文」再试。

**macOS / Windows 上能不能用录音**
能，除了需要麦克风权限，和手机完全一样。

**能不能不改代码就换别的模型**
在「接口地址」里填任何 OpenAI 兼容的网关即可，模型名自己填。

## 已知限制

- 单次音频 ≤ 120 秒、≤ 8 MiB（DeepSeek 语音接口的硬限制）
- 超过 800 KB 的笔记拒绝整篇改写，不会静默截断
- 改写全文会保留 frontmatter，但正文会被整段替换——请配合版本控制或「文件恢复」
- iPhone 无法用音量键触发

## 开发

```bash
npm install
npm run dev       # 监听构建
npm run build     # 类型检查 + 生产构建
npm test          # 用真实构建产物跑离线测试
npm run package   # 生成 dist/deepseek-voice-notes/
```

源码在 `src/`，`main.js` 是唯一运行产物，没有任何运行时依赖。测试加载的是打包后的真实 `main.js`（配一个桩 Obsidian 模块），所以测的是真正发出去的那份代码，不是它的副本。
