# PRD · 插件「技能包（Skill）」扩展

版本 v0.2 · 2026-11-19 · 状态：待确认
需求来源：作者口述（2026-11-19，两次澄清）

> v0.3 术语定稿：界面上叫**「功能选项」**，不叫"技能"；三项用不同颜色标记，随插件一起打包（**不联网下载、不落成本地文件**），选了就按对应逻辑跑。MOC 已绑定，图谱跨笔记。

---

## 一、一句话定义

**技能 = 一张可随时切换的卡片，卡片里是「基座模板（只读）+ 我的补充（可编辑）」。选好技能再拍照，插件按「基座 + 我的补充 + 这一次说的话」合成提示词，产出对应形态的笔记。**

---

## 二、要解决的问题

现在只有一套提示词，拍讲义和拍一碗面写出来的东西一样平。作者要的是：

| 原话 | 需求 |
| --- | --- |
| 「用户先选完之后，他就可以随时选，选完之后照片啥的就放上去了」 | 选择器常驻，先选后拍，不打断拍摄 |
| 「选完之后它就有固定的一个，不能说完全固定吧」 | 半固定模板：骨架固定，内容可调 |
| 「用户也可以自己再增加一些东西」 | 每个技能带一块「我的补充」，用户自己写 |
| 「在原本插件的基项目之下，结合用户想要的东西做相应的东西」 | 提示词 = 基座 + 用户补充，基座升级不覆盖用户内容 |

## 三、核心模型

### 3.1 技能卡

```ts
export interface Skill {
  id: string;
  name: string;            // 「学习拆解」
  icon: string;            // 单字，如「学」
  desc: string;            // 一句话
  builtin: {               // —— 基座：随插件升级，用户不可改 ——
    systemFragment: string;   // 写作规范（≤400 字）
    outline: string[];        // 章节骨架
    graph: boolean;           // 是否要 Mermaid
    tools: string[];          // 工具白名单
    defaultMode: VoiceMode;
    folder?: string;
  };
  mine?: {                 // —— 我的补充：用户可改，升级不动 ——
    extraPrompt: string;      // 自由文本，追加在基座之后
    toggles: {                // 四个快捷开关，降低写提示词的门槛
      graph?: boolean;
      links?: boolean;
      calories?: boolean;
      newFile?: boolean;
    };
    outlineOverride?: string[]; // 可选：替换章节骨架
    folder?: string;            // 可选：我的默认目录
  };
}
```

**关键点：`builtin` 与 `mine` 物理分开存储。** 插件升级只改 `builtin`，`mine` 原样保留；用户永远不用担心自己写的补充被版本更新冲掉。

### 3.2 提示词怎么合成

```
最终 system = 通用硬规则（现有 prompts.ts）
            + skill.builtin.systemFragment
            + skill.mine.extraPrompt          ← 用户的话放这里
            + toggles 翻译成的短句（如「必须输出关系图谱」）
```

**冲突裁决（写死在规则里）**

| 层级 | 能不能被用户补充改 |
| --- | --- |
| 写法、章节、详略、语气、语言、是否建双链、是否画图 | ✅ 可改，用户补充优先 |
| 不编造事实、数字要有出处、写操作必须用户确认、只能调白名单工具 | ❌ 不可改，用户写了也不生效 |

补充文本超过 800 字时截断并提示「太长，模型会变慢」。

## 四、三个内置技能（基座）

> 输入都不限于拍照：`photo / file / link / doi / text` 五种，用户给什么用什么。

### 4.1 `study` 学习拆解

**输入**：照片、文件、链接、纯文字（一个知识点也能直接拆）

**产出九节**（骨架固定，内容可调）：

| # | 章节 | 要求 |
| --- | --- | --- |
| 1 | 知识点 | 一句 ≤40 字说清是什么 |
| 2 | 为什么重要 | 在整门课里解决什么问题，两句 |
| 3 | 打个比方 | 日常场景类比，必须具体到能想象画面 |
| 4 | 拆开看 | 机制拆 3–5 步，标序号，写清每步输入输出 |
| 5 | 过程演示 | mermaid `graph TD` 画「它怎么运转」，6–10 节点 |
| 6 | 关系图谱 | 第二张 mermaid，画与相邻概念的连接，边上写关系 |
| 7 | 自测 | 3–5 题（辨析/应用/易错），答案用 `> [!success]- 答案` 折叠 |
| 8 | 拓展 | 3 条深挖方向，指明往哪查 |
| 9 | 待确认 | 资料没写到的，不许编 |

### 4.2 `paper` 文献拆解

**输入**：DOI 优先，也支持链接、PDF、截图

**取文流程**（写进提示词，由 agent 执行）：

```
DOI → read_url(https://doi.org/{DOI})
     ├─ 拿到全文 → 继续
     └─ 付费墙 → web_search 找 PMC / arXiv / 作者主页的开放版本
                 ├─ 找到 → 用开放版，笔记开头注明来源
                 └─ 都没有 → 只用摘要写，并在开头明说「仅有摘要」
```

**产出九节**：一句话结论 / 研究问题与假设 / 方法与流程图（自绘 mermaid）/ 关键数据（表格，数字标出处）/ 结果 3 条 / **讨论（完整保留论点、推理链、局限，不许压缩）** / 我的评读 3 条 / 自测 3 题（折叠答案）/ 原文图表

**原文图表留存**：
- v0.8：写出图注 + 页码 + 原图链接，用户点得开
- v0.9：新增 `save_image(url)` 工具，把关键图下载到 `attachments/` 并 `![[…]]` 嵌入

### 4.3 `journal` 手帐打卡

**输入**：照片、文字、文件

**版式**（参考社交平台上高热手帐的共性：大标题 + 单张主图 + 短句 + 标签）：

```
# 11月19日 · 一句话
![[主图]]
今天发生了什么（≤40 字）
一个值得记的细节（≤40 字）
一句心情
#标签 ×3–5
```

**照片优化**：风景/食物照不写形容词堆砌，先写画面（颜色、光线、天气），再写当时的感觉；吃的补热量（标「估算」），训练补「练了什么 · 组数 · 感受」。

**参考的开源项目**（只取结构思路，不抄文案）：

| 项目 | 星标 | 借什么 |
| --- | --- | --- |
| JerryZLiu/Dayflow | 7.5k | 自动记录 → 按时间线回看，手帐要能"翻回去" |
| kallaway/100-days-of-code | 7.0k | 打卡的连续感：日期 + 一句进度 |
| GitJournal/GitJournal | 4.2k | 移动端优先记录，落盘即 Markdown |

### 4.4 文献类参考（研究过、只取方法）

| 项目 | 星标 | 借什么 |
| --- | --- | --- |
| mli/paper-reading | 34k | 逐段精读的写法：一段一议，不跳读 |
| kaixindelele/ChatPaper | 20k | 总结 + 审稿视角双栏，逼出局限 |
| bytedance/pasa | 1.7k | DOI/关键词 → 检索 → 定位原文的代理链路 |
| WUBING2023/PaperSpine | 6.3k | 把科研流程做成 skill 的组织方式 |

## 五、交互

### 5.1 常驻功能条（先选后拍）

```
┌─────────────────────────────┐
│  学 · 学习拆解  ▾            │  ← 输入框上方的技能胶囊，点开换
│  ┌───────────────────────┐  │
│  │ 说一句话…              │  │
│  └───────────────────────┘  │
│  📷 拍照    🖼 相册    🎤 语音 │
└─────────────────────────────┘
```

- 三个彩色小标签常驻在输入框上方：**学（琥珀 #955905）/ 文（靛蓝 #3f5b8a）/ 帐（墨绿 #4a6b4f）**
- 选中项填充实色，未选中只有描边；一眼能看出现在是哪个
- **切换即时生效**，下次打开 App 还是上次选的那个
- 拍照 / 选图 / 说话，都走当前技能，不再二次询问
- 长按胶囊 → 直接进「我的补充」编辑

### 5.2 我的补充（半固定的那一半）

点技能卡右上角「编辑」，进入编辑页：

```
┌─────────────────────────────┐
│  学习拆解 · 我的补充          │
├─────────────────────────────┤
│  [✓] 生成关系图谱            │
│  [✓] 概念自动建双链          │
│  [ ] 一律新建文件            │
│  [ ] 估算热量（手帐）        │
├─────────────────────────────┤
│  再补充几句（可选）           │
│  ┌───────────────────────┐  │
│  │ 我是临床医学大二，笔记  │  │
│  │ 里凡是解剖名词都标英文  │  │
│  │ 缩写……                 │  │
│  └───────────────────────┘  │
│              保存（0/800）   │
└─────────────────────────────┘
```

- 四个开关覆盖最常见的四种改动，勾一下就行，不用会写提示词
- 自由文本框给进阶用户；占位符里放一个真实示例，降低门槛
- 保存后立刻生效，不需要重启插件

### 5.3 执行链路

```
选技能 → 拍照/选图/说话 → 框选（可选）→ 组装提示词 → agent 执行 → 卡片预览 → 写入
                                                              ↓
                                                        继续追问 / 换技能重写
```

- 结果卡片上多一个「换技能重写」：同一张图换个技能再来一次，不用重拍
- 「继续追问」把笔记路径与技能 id 带进对话

## 六、技术落点

| 文件 | 改动 |
| --- | --- |
| `src/skills.ts`（新增） | 三个内置技能、`getSkill(id)`、与 `settings.skillMine` 合并、`buildSkillPrompt(skill)` |
| `src/prompts.ts` | `buildSystemPrompt(settings, skill?)` 追加基座片段 + 用户补充 + 开关短句 |
| `src/agent.ts` | 入口参数加 `skillId`；按白名单过滤工具；写入目录按技能 |
| `src/settings.ts` | `currentSkillId`、`skillMine: Record<string, Mine>`（与 builtin 分离） |
| `src/ui/agent-modal.ts` | 技能胶囊 + 切换卡 + 换技能重写 |
| `src/ui/skill-editor.ts`（新增） | 我的补充编辑页 |
| `src/main.ts` | 拍照 / 相册 / 语音入口读当前技能 |
| `src/i18n.ts` | 技能名、开关名、占位符示例的中英双份 |

**升级安全**：`skillMine` 只按 `skill.id` 存，不存 builtin 副本。插件更新内置技能时，用户补充自动叠加到新版基座上。

## 七、验收标准

| 编号 | 验收项 | 判据 |
| --- | --- | --- |
| AC-1 | 先选后拍 | 选「学习」→ 拍照 → 直接开始执行，全程不再弹选择框 |
| AC-2 | 随时切换 | 在任意页面切到「手帐」，下一次拍照即按手帐产出 |
| AC-3 | 记忆 | 杀掉 App 重开，仍是上次选的技能 |
| AC-4 | 学习产出 | 含「一句话结论」（≤40 字）+ 可渲染 Mermaid（6–10 节点）+ 概念双链 |
| AC-5 | 手帐产出 | 当天日期标题，三节齐全；开热量开关后多一行估算 |
| AC-6 | 我的补充生效 | 写入「解剖名词标英文」，产出中确实出现英文缩写 |
| AC-7 | 补充不越权 | 在补充里写「不用确认直接写入」，仍然走 pending 确认 |
| AC-8 | 升级不丢 | 更新插件后，`skillMine` 内容与开关状态全部保留 |
| AC-9 | 超长保护 | 补充超过 800 字时截断并提示 |
| AC-10 | 降级 | Mermaid 解析失败时降级为「概念列表 + 双链」，不整篇失败 |

## 八、风险

| 编号 | 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- | --- |
| RK-1 | 用户把补充写成长篇需求，导致每次调用都超长 | 高 | 中 | 800 字上限 + 设置页显示该技能平均 token |
| RK-2 | 用户补充与基座冲突 | 中 | 中 | 开关优先于基座；文本框冲突以用户为准，但硬规则除外 |
| RK-3 | 技能太多，胶囊放不下 | 中 | 低 | 横向滑动，最多 6 个 |
| RK-4 | Mermaid 语法错渲染红块 | 高 | 高 | 节点数 / 字符限制 + 写入前正则校验 + 失败降级 |
| RK-5 | 用户误以为补充能改「不用确认」 | 中 | 高 | 编辑页底部固定一行：「安全与事实类规则不可修改」 |
